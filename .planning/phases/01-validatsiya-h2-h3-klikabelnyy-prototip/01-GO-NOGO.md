## Критерии (D-07, дословно)

- **H2 go** = ≥ 2 преподавателя согласны на пилот — считается как **≥ 2 интервью с commitment-уровнем 2** (назван курс/группа + срок + принятый следующий шаг с датой и владельцем; уровень 2 валиден только с дословной цитатой + конкретикой, иначе деградирует до 1 — лестница в гайде H2).
- **H3 go** = **completion > 60%** по таблице N→минимум (completion = дошёл до финальной сводки без подсказок по механике; assisted не считается):

| N респондентов | Минимум completions для >60% | Фактический порог |
|---|---|---|
| 5 | 4 | 80% (3/5 = 60% — не > 60%) |
| 6 | 4 | 66.7% |
| 7 | 5 | 71.4% (4/7 = 57.1% — нет) |
| 8 | 5 | 62.5% |

Общий итог: **GO** — обе гипотезы go → Phase 2 без изменений скоупа. **NO-GO** — хотя бы одна no-go → до планирования Phase 2 обновить root `STATE.md`, `DECISIONS.md`, пересмотреть DOCS-05/DOCS-06 и сегментные приоритеты.

### Агрегат H3 (из секции «H3: Юзабилити-тест прототипа (Phase 1)»)

- Сессий проведено: N = ___ (сухой прогон не в счёт)
- Completions (unassisted): X = ___ → минимум по таблице для этого N: ___ → **> 60%? да/нет**
- Поиск числа (задание 3, ∂L/∂W₁[1,0], шаг 12): медиана ___ сек, максимум ___ сек; прошли порог < 10 сек: ___ из N
- Топ-3 шага-проблемы (по тупикам и моментам непонимания): 1) шаг ___, 2) шаг ___, 3) шаг ___
- **Вердикт по wall-of-numbers** (критерий 3 ROADMAP — выбрать одно):
  - [ ] порог откалиброван (медиана < 10 сек, стена не возникает)
  - [ ] стена поймана (медиана ≥ 10 сек или системные «не нашёл» — описать шаги-проблемы)
  - [ ] не возникает (числа на экране не создают проблемы поиска)

## Процедура записи вердикта (§6.4 RESEARCH, D-07)

1. Заполнить агрегаты в `EVIDENCE.md` (обе секции) — цитаты и числа из записей, правила подсчёта не менять.
2. Заполнить секцию «Вердикт» ниже — по критериям выше, с датой.
3. Агент (Task 4 плана 01-04) переносит решение: строка «Вердикт H2/H3» в root `STATE.md` (секция «Какая гипотеза проверяется сейчас») + `last_activity` в `.planning/STATE.md`.
4. Только при NO-GO по любой гипотезе: до планирования Phase 2 — запись в root `DECISIONS.md` и пересмотр DOCS-05/DOCS-06 и сегментных приоритетов. При GO — Phase 2 планируется без изменений скоупа.

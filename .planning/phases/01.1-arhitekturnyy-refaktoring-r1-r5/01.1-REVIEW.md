### WR-01: Space на сфокусированном SVG-якоре диаграммы — двойной эффект: advance + мгновенный сброс drill

**File:** `src/ui/StepControls.tsx:17-26` (совместно с `src/ui/ArchitectureDiagram.tsx:139-144, 193-198`)
**Issue:** Guard «Space на сфокусированной кнопке обрабатывает нативный click» проверяет только `event.target instanceof HTMLElement && event.target.tagName === 'BUTTON'`. Якоря диаграммы (`.diag-hit` line/circle) — `SVGElement`, не `HTMLElement`, и имеют собственные `onKeyDown` (Enter/Space → `run.openDrill(ref)`). При нажатии Space на сфокусированном ребре/узле: (1) React-обработчик якоря открывает drill, (2) затем window-обработчик (`useEffect`) исполняет `run.advance()` — а `advance()` делает `this.drill = null` (`src/run/runState.ts:292`) и шагает прогон. Итог: клавиатурный a11y-путь «Space → drill» на диаграмме не работает, walkthrough незаметно для пользователя шагает. e2e клавиатуру на SVG-якорях не проверяет.
**Fix:**
```ts
const onKeyDown = (event: KeyboardEvent): void => {
  const t = event.target
  // Space на сфокусированном кнопко-якоре (HTML button ИЛИ SVG role="button") — его дело
  const isButtonAnchor =
    (t instanceof HTMLElement && t.tagName === 'BUTTON') ||
    (t instanceof Element && t.closest('[role="button"]') !== null)
  if (event.key === ' ' && isButtonAnchor) return
  // ...
}
```
(Проверки `event.defaultPrevented` недостаточно: для HTML-кнопок keydown не prevented, и тогда Space дал бы двойной advance — window + нативный click.)

### WR-02: Тултипы tier 1 молча теряют формулу на ops 8/10 (sigmoid-grad, tanh-grad); hover по узлам ŷ/a1 в этих шагах без тултипа

### WR-03: Экспандеры ставят display-минус в знак экспоненты («e−8») — нарушение контракта нотации D-06/UI-SPEC

**File:** `src/tensor/expanders.ts:81-85`
**Issue:** `fmt()` делает `String(Number(n.toPrecision(4))).replaceAll('-', '−')` — заменяет ВСЕ дефисы, включая знак экспоненты: `-1.234e-8` → `−1.234e−8`. Контракт (`src/format/numbers.ts:16-23`, `toDisplayMinus`, образец UI-SPEC «−2.451e-5») требует ASCII после e/E. Это не теоретично: градиенты и веса уже на первых эпохах бывают < 1e-3 по модулю (например ∂L/∂b1 ≈ 0.0034), а дальше уменьшаются — в формулах тултипов появятся строки вида «e−7», которые студент может прочитать как вычитание («e − 7»). Единственное место форматирования чисел обойдено (D-06 «Unit Policy»).
**Fix:**
```ts
function fmt(n: number): string {
  if (!Number.isFinite(n)) return String(n)
  if (n === 0) return '0'
  const s = String(Number(n.toPrecision(4)))
  return s.replace(/-/g, (ch, off: number) => (off > 0 && /[eE]/.test(s[off - 1]!) ? ch : '−'))
}
```
(Импорт из `src/format/numbers.ts` невозможен — граница src/tensor/ R2; локальный guard зеркалит семантику `toDisplayMinus`.)

### IN-02: BCE без защиты от насыщения sigmoid — ±Infinity/NaN при p → 0/1

**File:** `src/tensor/ops.ts:76-87`
**Issue:** `bceForward` считает `Math.log(p)` / `Math.log(1-p)`, `bceGradP` делит на `p*(1-p)`. При |z2| ≳ 37 `Math.exp(-z2)` андерфлоуит и sigmoid возвращает 1.0 bit-exact → L = Infinity, градиент NaN. В XOR-сценарии v1 недостижимо (|z2| ≤ Σ|W2|·|a1| + |b2|, a1 ∈ (−1,1)), и семантика совпадает с эталонным Python-генератором, но эпохи бесконечны и lr = 0.5 — зафиксировать ограничение.
**Fix:** При расширении сценариев (спираль/MNIST) клампить p в [eps, 1−eps] или перейти на BCE через logit-space; сейчас достаточно дописать ограничение в док-комментарий `bceForward`.

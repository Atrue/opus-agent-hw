# Phase 3 — UI Design Contract

> Фаза — UI-платформа, не новый экран: миграция пересобираемых примитивов на кит shadcn
> (визуальная идентичность с DESIGN.md — канон D-25) + анимация трёх существующих точек
> взаимодействия. Контракт отвечает на вопрос «какие визуальные и интеракционные
> обязательства нужны фазе»: (1) токен-мост кит ↔ DESIGN.md, (2) карта миграции компонентов
> с нулевым визуальным изменением, (3) анимационный контракт трёх обязательных точек с гейтами
> reduced-motion/print/lecture и e2e-детерминизмом, (4) покрытие состояний kit-компонентов.
> Решения D-38…D-48 (03-CONTEXT.md) — LOCKED, здесь не пересматриваются.

## Токен-мост: кит ↔ DESIGN.md (D-39)

**Правила моста (контракт, не механика):**

1. Единственный источник правды — `@theme`-токены DESIGN.md в `src/index.css`. Все
   CSS-переменные, которые потребляет кит (`--background`, `--primary`, `--radius`, …),
   объявляются **алиасами** (`var()`-ссылки на существующие токены) — hex-дублей нет.
2. Дублирования палитры в shadcn-формате нет: правка палитры DESIGN.md распространяется
   на кит автоматически (проверяется планом тривиальным тестом вычисленных стилей).
3. Светлой темы нет — токены объявляются один раз; механизм `.dark` не используется.
4. **Разрешение именовых коллизий по роли, не по имени**: имена слотов shadcn (`primary`,
   `secondary`, `accent`) ≠ семантика DESIGN.md (мята/циан/амбер). Слот получает значение
   по визуальной роли компонента; семантические акценты остаются за DESIGN.md-токенами.
   Пример: слот `--primary` (CTA-кнопка кита) = `primary-container` `#10b981`, а DESIGN.md
   `primary` `#4edea3` (мята = forward) остаётся акцентом и hover-состоянием CTA.
5. Механика (`@theme inline` против обычных алиасов, точная арифметика `--radius`) —
   исследовательская деталь (03-CONTEXT, Claude's Discretion); визуальный результат —
   константа таблицы ниже.

**Карта алиасов** (слот shadcn → токен-источник DESIGN.md → результирующий hex; точность
hex — цель миграции, вычисленные стили совпадают с текущими):

| Слот кита | Токен-источник | Hex | Примечание |
|-----------|----------------|-----|------------|
| `--background` / `--foreground` | `--color-background` / `--color-on-surface` | `#0f131c` / `#dfe2ee` | фон приложения |
| `--card` / `--card-foreground` | `--color-surface-container-low` / `--color-on-surface` | `#181c24` / `#dfe2ee` | база карточек |
| `--popover` / `--popover-foreground` | `--color-surface-container-high` / `--color-on-surface` | `#262a33` / `#dfe2ee` | поверхность тултипа — совпадает с текущим `num-hint` |
| `--primary` / `--primary-foreground` | `--color-primary-container` / `--color-on-primary-container` | `#10b981` / `#00422b` | CTA-кнопка (коллизия имён — правило 4); hover CTA = `--color-primary` `#4edea3` |
| `--secondary` / `--secondary-foreground` | `--color-surface-container` / `--color-on-surface` | `#1c2028` / `#dfe2ee` | тихая заливка вложенных блоков; циан DESIGN.md — не здесь (правило 4) |
| `--muted` / `--muted-foreground` | `--color-surface-container-high` / `--color-on-surface-variant` | `#262a33` / `#bbcabf` | вторичный текст на приглушённой поверхности |

| `--destructive` / `--destructive-foreground` | `--color-error` / `--color-background` | `#ffb4ab` / `#0f131c` | потребителей нет — алиас впрок |
| `--border` / `--input` | `--color-outline-variant` | `#3c4a42` | hairline-бордеры; фон инпута — container-lowest `#0a0e16` (DESIGN.md §5) |

| `--radius` | — | `4px` | масштаб кита алиасится на шкалу DESIGN.md §4: **2 / 4 / 8 / 12**; карточка = 2, кнопка/инпут = 4; `> 12px` запрещён |
| `--font-sans` / `--font-mono` | уже объявлены | Geist / JetBrains Mono | — |

Слоты `chart-*` и `sidebar-*` не объявляются (нет потребителей). Okabe-Ito роли
(`--color-neg/pos…`) в мост не входят — они остаются прямыми токенами SVG/чисел.

## Карта миграции: hand-rolled → кит (D-38)

Общий инвариант миграции: **testid, RU-строки, e2e-селекторы (17 проверок), aria-контракты
не меняются** (D-38); двойной прогон бит-идентичен; вычисленные стили migrated-элементов
совпадают с текущими до значений токенов. Визуальный диф до/после — скрин-ревью владельцем
(baseline регенерируется один раз по итогам миграции).

| Текущий примитив (CSS/код) | Потребители | Мигрирует на | Визуальный контракт (конечное состояние = сегодняшнее) |
|---|---|---|---|
| `.btn` (quiet) | StepControls («Сброс», «Запустить эпоху»), зум графа | `Button` variant `quiet` | прозрачный фон + 1px `outline-variant`, radius 4, min-height 40, hover `container-high` + бордер `outline`, active `container-highest`, nowrap |
| `.btn-primary` | StepControls («Шаг», «Следующая эпоха») | `Button` variant `default` (CTA) | заливка `primary-container`, текст `on-primary-container`, hover `bg-primary`, active затемнее (mix 85% black); **единственная заливка на экране**; «Шаг» никогда не disabled |
| `toggle-lecture` (aria-pressed) | App, шапка | `Button` variant `toggle` (quiet + pressed-состояние) | pressed: прозрачный фон, бордер и текст `primary` (мятный контур, не заливка) |
| `.graph-zoom .btn` | ComputationGraph | `Button` size `icon-sm` | компакт 34×min, padding 2×8; пределы зума 0.5–2.0 шаг 0.25 не меняются |
| `.card` + `.card-head/-title/-meta` | ResultPanel, ExamplesPanel, LossChart, EpochSummary, LinkPanel, OperationPanel | `Card` (+Header/Title/мета-слот) | container-low, radius **2**, padding 16, gap 8, `shadow-card`; шапка = иконка + headline-sm (SG) + правый мета-бейдж |
| `NumberHint` (@floating-ui/react) | числа графа/панелей (tier-1) | `Tooltip` (Radix) — **после пилота D-40** | портал `document.body`, z-index 50 (поверх SVG, D-35 фикс 2), offset ~6, flip/shift у краёв, hover (restMs 60, delay 120) + focus, Esc-dismiss, `aria-describedby`; контент идентичен (метка + значение + градиент); мобильный тап → drill, не тултип. Пилот не прошёл — `@floating-ui/react` остаётся только в NumberHint |
| `.kbd` | статус-бар (Space, Esc) | `Kbd` | mono 11px, container, бордер 1px с усиленным низом 2px, radius 4 |
| `<details data-testid="link-history">` | LinkHistory | `Collapsible` (Radix) — **пилот** интеракции | testid `link-history`, триггер = бывший `summary` (тот же текст/поведение раскрытия); интеракция не воспроизводится — остаётся `<details>` |

**Обёртки** (группа контролов `role="group"`, скролл-контейнеры ленты `.step-nav`/`.step-band`)

панели чисел, drill-down, LossChart) — см. Component Inventory, не мигрируют.

`tw-animate-css` обеспечивает enter/exit radix-компонентов (тултип, collapsible): те же

## Анимационный контракт (D-47/D-48)

Движок выбора (GSAP / motion / CSS-only) — предмет ресёрча (D-45) и решения владельца;
**этот спек контрактирует поведение, а не библиотеку**. Числа, зависящие от ресёрча
(точные длительности, easing-кривые, техника интерполяции), записаны параметризованно:
диапазон + «точное значение — план по итогам ресёрча».

### Градус (D-48, DESIGN.md §8)

- Микровзаимодействия (действие пользователя → отклик): **150–400 мс**, функциональные,
  ease-out/ease-in-out, одиночные (не циклы). Точные значения — план по итогам ресёрча.
- Континуальные индикаторы сохраняют канон DESIGN.md §8: пульс активной пилюли 2 s,
  ping 1 s, градиентная волна по рёбрам ~1.2 s linear loop. Конверт 150–400 мс на них
  **не распространяется** — это индикаторы состояния, не микровзаимодействия.
- Без декоративных циклов вне активного действия (D-48); «движение = смысл» (§1/§8).
- Анимации — презентационный слой: числа появляются в DOM синхронно с шагом (NFR-01
  < 100 мс не включает анимацию), ввод не блокируется, спиннеры поверх вычисленных чисел
  запрещены (§10). Анимируются `opacity`/`transform`/цвет — не layout соседей.

### Три обязательные точки (D-47)

**1. Подсветка активного шага — «подсветка приезжает» (D-48).**
При смене активного шага визуальный акцент перемещается к новой позиции, а не появляется
скачком в двух местах:

| Аспект | Контракт |
|---|---|
| Лента шагов | акцент (ring + тинт) приезжает к новой пилюле: travel 150–400 мс, ease-out; движется подсветка, пилюли не меняют layout (grid-auto-columns стабилен); автоскролл к активной — smooth, при reduced-motion `behavior: auto` (существующий контракт) |
| Пульс активной пилюли | остаётся каноном: оверлей `primary/10`, 2 s loop (§8) — индикатор «текущего шага», не микровзаимодействие |
| Граф | амбер-подсветка группы активной op (обводка/тинт станций, кейсинг исходящих рёбер) приезжает fade-in в конверте 150–400 мс; конечное состояние = текущие цвета (тертиарная обводка, тинт 12%); предыдущая группа гаснет тем же конвертом |
| Значения шага | fade+rise ≤ 200 мс, ease-out (§8, канон, без изменений); значения приходят пачкой |

**2. Коллапс/раскрытие нейрона (рамка из 2.1 — сейчас мгновенно).**
Двойной клик / Enter по заголовку рамки схлопывает содержимое плавно (D-48):

| Аспект | Контракт |
|---|---|
| Длительность/характер | 150–400 мс, ease-in-out (точное значение и техника — план по итогам ресёрча: FLIP/transform на SVG-группах, WAAPI, CSS, GSAP/motion) |
| Конечные состояния | бит-идентичны сегодняшним: раскрытая рамка (bbox членов + FRAME_PAD) и квадратный блок-нейрон (живое z, цепь x → n → z → σ → ŷ); геометрия остаётся чистой функцией структуры (`geometry.ts`/`frames.ts`) — анимация интерполирует между двумя детерминированными кадрами, не порождая новых layouts |
| Прерываемость | повторный двойной клик в середине анимации перебивает её и ведёт к новому конечному состоянию (interrupt-restart, без очереди и без блокировки ввода) |
| Читаемость | живые числа (`station-value` z) остаются в DOM и читаемы; промежуточные кадры не меняют числа |

**3. Поток forward/backward (бегущий пунктир по рёбрам).**
Существующий CSS-only «бегущий пунктир» с направлением по фазе (`data-flow`) дорабатывается
до «волны, читающей направление backprop» (D-48): волна амбер-пунктира движется по активным
рёбрам **от выхода ко входу** на backward-фазе (и по ходу вычисления — на forward);
направление и цвет кодируются фазой (существующая семантика). Параметры канона §8
(dash-offset ~1.2 s, linear, loop) сохраняются как базовые; уточнение техники/скорости —
решение ресёрча (CSS-only остаётся кандидатом по умолчанию, D-45). Активные рёбра —
исходящие рёбра группы шага (§9a), поток живёт на ребре (2.1-01).

### Гейты (общие для всех точек и для enter/exit кит-компонентов)

| Гейт | Контракт |
|---|---|
| `prefers-reduced-motion: reduce` | несущие анимации (travel/pulse/ping/dash/коллапс/rise, enter/exit кит-компонентов) отключаются **полностью**; остаются только цветовые переходы ≤ 150 мс (DESIGN.md §8, D-48). Существующий глобальный гейт `animation: none !important` — легальная (более строгая) реализация; e2e-ассерт «computed `animation-name` активного `.diag-flow` === `none`» обязан оставаться зелёным |
| `@media print` | статичный кадр: существующий print-блок расширяется на новые анимации (travel, коллапс-переходы, enter/exit кит-компонентов) — печать всегда ловит конечное состояние |
| `.lecture` (лекционный режим) | анимации смысла **не выключаются**: поток — дидактический контент (R5 §4.2 — решение сохранено); коллапс и приезд подсветки — одиночные функциональные действия пользователя, детерминированно повторяемые на проекторе |
| e2e-детерминизм | все 17 проверок идут под `emulateMedia({ reducedMotion: 'reduce' })` + `deviceScaleFactor: 2`; **двойной прогон бит-идентичен** (01.1-04). Тесты не ждут анимаций — значения в DOM синхронно. Селекторы/testid/RU-строки не меняются (D-38) |
| NFR-01/02 | анимации вне критического пути шага (< 100 мс без их учёта); движок `src/tensor/` и инварианты «drill-down = движок», «пошагово = fast-forward» не трогаются |

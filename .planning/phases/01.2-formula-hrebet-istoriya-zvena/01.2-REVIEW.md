## Warnings

### WR-01: Инверсия слоёв — run-слой импортирует тип из UI-слоя

**Classification:** WARNING (maintainability / module boundary)
**File:** `src/run/runState.ts:17`, `src/run/history.ts:16`
**Issue:** `src/run/runState.ts:17` и `src/run/history.ts:16` импортируют `SegmentId` из `../ui/chainLinks`. Направление зависимости развёрнуто: нижний слой (прогон) теперь зависит от верхнего (UI), и тип UI-концепции («звено цепи») вшит в публичный API run-слоя (`LinkSelection.segment`, `selectLink()`, `linkHistoryOf()`). Сегодня импорт type-only (стирается при компиляции, цикла нет: chainLinks → run/scenario, не runState), но стоит chainLinks понадобиться что-то из runState — возникнет настоящий цикл модулей. oxlint-граница это не ловит (правило описывает только src/tensor).
**Fix:** Перенести `SegmentId` (и при желании `LinkSelection`) в `src/run/` (например, в runState.ts или отдельный `src/run/segments.ts`) и ре-экспортировать из `src/ui/chainLinks.ts` для UI-кода:

```ts
// src/run/runState.ts
export type SegmentId = 'x' | 'z1' | 'a1' | 'z2' | 'yhat' | 'L' | 'W'
// src/ui/chainLinks.ts
export type { SegmentId } from '../run/runState'
```

### WR-02: «Живые числа» панели звена читают несубскрибированное состояние движка — свежесть держится на перерисовке родителя

**Classification:** WARNING (robustness / React-quality)
**File:** `src/ui/LinkPanel.tsx:28-64,69,81`, `src/ui/LinkHistory.tsx:143-145`
**Issue:** `liveValues()` (LinkPanel.tsx:28) читает мутируемые тензоры движка (`run.activeCursor.tensors`, `run.model.*`) прямо во время рендера, при этом LinkPanel подписан только на `r.selection` (LinkPanel.ts:81), а LinkHistory — на `r.sampleHistory` (LinkHistory.tsx:143) и_props. `useRunSlice` сравнивает срез через `Object.is` — при `advance()` selection не меняется, собственная подписка панели не перерисовывает компонент. Сегодня числа обновляются только потому, что App подписан на `currentRecord`/`screen` и перерисовывает всё дерево целиком (App.tsx:56-63), включая несубскрибированные дети. Это хрупкая связность: обёртка LinkPanel/LinkHistory в `React.memo`, вынос из дерева App или смена селекторов App молча заморозит «живые числа» и live-строку «сейчас», contra собственному контракту компонента («живые тензоры прогона… после fast-forward числа свежее»). Отметки version (R4 §6.2) для этих чтений не задействованы.
**Fix:** Подписать панель на счётчик мутаций явно — `const version = useRunSlice((r) => r.version)` в LinkPanel (или в отдельном `<LiveNumberRow>`), этого достаточно: version инкрементируется на каждую операцию/selection/reset; сами числа остаются прямым чтением движка (инвариант «drill-down = движок» сохраняется):

```tsx
export default function LinkPanel() {
  const selection = useRunSlice((r) => r.selection)
  useRunSlice((r) => r.version) // перерисовка на каждую мутацию прогона — живые числа
  ...
}
```

# Phase 2.1 CONTEXT — Правки визуализации графа вычислений

## Зачем

Владелец (D-35, 2026-11-16) сформулировал 5 фиксов читаемости графа: граф должен читаться
как формула без шума. Всё — render-слой (spec.render данные + UI графа); движок, числа
ScenarioModel, инварианты NFR-02 и эталоны не трогаются.

## Пять фиксов (формулировки владельца → техническое прочтение)

| # | Фикс (слова владельца, ROADMAP критерии 1–5) | Техническое прочтение |
|---|---|---|
| 1 | «Убрать с графа op:update "W ← W − η·∂L/∂W"» — update-узел уходит вслед за loss-узлом (расширение D-32) | Удалить `op:update` узел + `upd()`-рёбра из render обоих сценариев; kind 'update' уходит из GraphNodeKind/рендера/CSS; SGD-шаг, панель звена W, W-сегмент формулы-строки, drill-down — без изменений (это не render-узлы); stepGroups шага sgd = только параметры; segment W symbolNodes η/∂L/∂W → параметры |
| 2 | «Тултипы NumberHint поверх графа — не перекрываются рёбрами, узлами и звеньями SVG; позиционирование Floating UI сохраняется» | Числа узлов графа получают tier-1 тултип NumberHint (портал document.body, z-index 50, Floating UI — уже используется в OperationPanel); hover-тултипы рёбер (g-tip, CSS-only SVG) рендерятся верхним слоем SVG ПОСЛЕ узлов (SVG paint order) — больше не перекрываются узлами |
| 3 | «Промежуточный результат не порождает звено-узел: x·w[0,0] — это и есть Wx, ребро сразу к "+" без пересадки; b[0] — под/над "*"» | Удалить узлы Wx/W1x[j]/W2a1 (промежуточные результаты matvec): ребро op:matvec → op:add напрямую (значение живёт на op-станции matvec и в drill); b-узлы (b[0], b1[j], b2[0]) переносятся в колонку своей «·»-опы (под/над ней), ребро к своей «+»-опе; именованные звенья цепи (z1, a1, z2, ŷ) ОСТАЮТСЯ узлами |
| 4 | «Рамка-нейрон с названием ("Нейрон 1") и полупрозрачным фоном; двойной клик — коллапс в квадратный блок (x → n → y), повторный — раскрытие» | Рамки декларируются данными в spec.render (массив frames: id, title, узлы); neuron — 1 рамка, XOR — 4 (3 скрытых + выходной); коллапс — локальный UI-state, мгновенный (без анимации — анимации фаза 4); в коллапсе: квадратный блок с именем + живое выходное значение нейрона; a11y: заголовок рамки — кнопка (Enter/Space) |
| 5 | «Узлы квадратные (1:1), значение не влезло — над блоком» | NODE_W=NODE_H (квадрат); детерминированное правило влезания форматированного значения (formatKey, табличные цифры) в блок: не влезло — значение рендерится над блоком, блок не растягивается |

## Открытые допущения (закрыты решением по умолчанию, отметить на ревью планов)

- A1: рамки-нейроны декларируются в ОБЕИХ сценариях (neuron 1, XOR 4); если ревью/UAT покажет перегруз XOR — отключается одним флагом спека (дёшево).
- A2: коллапс-блок показывает имя + живое выходное значение нейрона (выход = тензор последней опы нейрона); клик по блоку = drill выходного значения, двойной клик = раскрытие.
- A3: правило влезания: formatKey-строка ≤ 8 символов — внутри блока, длиннее — над блоком (константа CAPACITY, юнит-гейт детерминизма).
- A4: «н/д» и градиент «∂ = …» под блоком — сохраняются как есть (не в счёт влезания значения).

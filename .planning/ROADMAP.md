# Roadmap: Backprop Trainer — Интерактивный тренажёр обучения нейросетей

## Overview

Путь от идеи до R1: сначала дёшево проверить самые рискованные допущения (D-18 — 5 проблем-интервью с преподавателями на H2 и юзабилити-тест кликабельного прототипа XOR на H3, до какого бы то ни было кода), затем построить собственный тензорный движок float64 (PyTorch-имена, юнит-эталоны — NFR-02) и на нём MVP — полный walkthrough первого урока «один нейрон» с числами и drill-down до формулы (MVP R1; ревизия 2026-11-09 — вместо XOR сценарий «один нейрон»), затем расширить до библиотеки сценариев XOR → спираль → MNIST с нулевым порогом входа и лекционным режимом, и наконец включить замер прироста понимания (валидация H1) с анонимной аналитикой, доступностью и подготовкой к пилотам. Каждая фаза завершается проверяемой способностью продукта.

> Ревизия 2026-11-02 (архитектурное ревью фазы 01, `.planning/reviews/01/DECISIONS.md`): forward-only UX (эпохи, fast-forward, сброс; «назад» исключён), тензорный движок вместо Python-конвейера golden-фикстур, reload = честный сброс. Между фазами 1 и 2 вставляется под-фаза 1.1 «Архитектурный рефакторинг R1–R5».
>
> Вставка 2026-11-05 (ТЗ владельца, 9 пунктов): под-фаза 01.2 «Формула-хребет и история звена» — UI-правки экрана (формула-строка, звенья цепи, примеры, история звена) до отдельного старта фазы 2, чтобы не смешивать их с MVP-walkthrough.
>
> Ревизия 2026-11-09 (владелец, планирование фазы 2 — `02-CONTEXT.md`): MVP-walkthrough фазы 2 строится на сети из **одного нейрона** (первый урок; XOR-MLP переносится в прогрессию сценариев фазы 3); функция потерь исключается из визуализации графа (в расчётах остаётся); добавлены инженерные стандарты фазы — строгый oxlint-линтер (первоначально airbnb; ревизовано владельцем при ревью планов 2026-11-09 — ESLint не вводится, правило явного апрува на изменения конфига сохранено), модульная структура папок (тесты рядом с кодом, 1 экспорт на файл, README модуля), декомпозиция Value на чистые функции градиентов, общий интерфейс модели (модель → граф → метки рендера), отказ от собственных полей window.
>
> Ревизия 2026-11-16 (владелец, D-35): вставлена фаза **2.1 «Правки визуализации графа вычислений»** (5 UI-фиксов: убрать update-блок с графа, тултипы поверх графа, рёбра без промежуточных звеньев-результатов, рамка-нейрон с коллапсом x→n→y, квадратные блоки); фаза **3** перепрофилирована — библиотека ровно из 3 сценариев (1-1-1 «2x+10», 2-2-1 «10x+y», 2-(3-3)-1 спираль TF) + переключатель сценариев + клиентский роутинг вместо хэша + блок «Примеры» с режимами отображения; фаза **4** = shadcn + анимации (ресёрч GSAP/motion/Spline); «Замер понимания и подготовка к пилоту», MNIST и сценарии AND/XOR — parking без планов. **Mode:** mvp
**Depends on**: Phase 1
**Requirements**: DOCS-01, DOCS-02, UX-02
**Success Criteria** (what must be TRUE):
  1. Пользователь сам исполняет каждый шаг forward- и backward-pass сценария «один нейрон» и видит входы, выходы, активации и градиенты операции конкретными числами; индикатор показывает «эпоха N · шаг M» и фазу прохода; экран завершения эпохи (L до/после, точность) продолжается следующей эпохой, NaN и пустых состояний нет

### Phase 2.1: Правки визуализации графа вычислений (INSERTED)

**Goal:** Граф вычислений читается как формула без шума: блок обновления весов уходит с графа вслед за loss-узлом (расширение D-32), тултипы перекрывают граф, результаты операций не порождают промежуточных звеньев-узлов, звенья нейрона объединены рамкой с коллапсом в квадратный блок (x → n → y), узлы квадратные. Движок, числа ScenarioModel и инварианты NFR-02 не меняются — правки только render-слоя (spec.render + UI графа)
**Mode:** quick-insert
**Depends on:** Phase 2 (закрывается после реверификации цикл 2 + UAT)
**Requirements:** нет новых (уточнение DOCS-02)
**Success Criteria** (what must be TRUE):
  1. Узел `op:update` с меткой «W ← W − η·∂L/∂W» не отображается на графе; SGD-шаг, панель звена W, W-сегмент формулы-строки и формулы drill-down работают без изменений (расширение D-32: update-узел уходит вслед за loss-узлом)
  2. Тултип числа (NumberHint) всегда рендерится поверх графа — не перекрывается рёбрами, узлами и звеньями SVG; позиционирование Floating UI сохраняется
  3. Промежуточный результат операции не становится отдельным звеном-узлом: значение x·w[0,0] — это и есть Wx, ребро идёт от точки-операнда сразу к операции «+» без пересадки; b[0] смещён влево — находится под/над операцией «*»
  4. Звенья нейрона объединены рамкой-контейнером с названием («Нейрон 1») и слабым полупрозрачным фоном; двойной клик по рамке схлопывает содержимое в один квадратный блок-нейрон, повторный двойной клик раскрывает обратно (уточчено UAT-ревью 2026-11-17, D-36: рамка охватывает внутренние веса и вычисления — параметры w/b + «·»/«+»; значения z/a1/ŷ, активации и входы — вне рамки; цепь при коллапсе x → n → z → σ → ŷ)
  5. Узлы-блоки графа квадратные (пропорция 1:1, не прямоугольные); если значение не помещается внутри блока, оно выводится над блоком, не растягивая его
  6. Инварианты «drill-down = движок», «пошагово = fast-forward» и эталоны NFR-02 не тронуты; e2e-базлайн регенерирован; `pnpm test && pnpm lint` зелёные

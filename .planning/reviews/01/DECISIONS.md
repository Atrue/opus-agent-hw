# Ревью фазы 01 — журнал решений

> Архитектурное ревью по 5 направлениям пользователя. Обсуждение последовательное: каждое решение — после апрува. Ресерчи: `.planning/reviews/01/R1..R5-*.md`.
> Дата: 2026-11-02. Статус: R1–R3 решены, R4 в обсуждении, R5 ожидает.

## R1 — ООП-тензорный движок ✅ РЕШЕНО

**Решение (Путь 1, «B сразу»):**
- `Tensor` op-уровня (векторизованные операции над Float64Array) + **ленивые скалярные экспандеры** drill-down (`expanders.ts` используют `value.ts` — A-математика по требованию)
- **Инвариант-тест «drill-down = движок»**: скалярное раскрытие совпадает с элементом векторного результата (CI, per-op)
- Имена/паттерны PyTorch: `requiresGrad`, `zeroGrad`, `SGD.step()`, F-лоссы (`functional.ts`)
- **Recorder-флаг**: `record: true | false` в операциях (пошаговый режим пишет StepRecord; fast-forward/массовые прогоны — нет); числа идентичны в обоих режимах (код один)
- Мутационная семантика как в Python: forward создаёт новые тензоры; `grad` аккумулируется на месте (`+=`); `step()` мутирует `data`. Граница иммутабельности — снапшоты на выходе (история/таблица весов)
- **НЕ берём до R2**: `Module`/`Sequential` (прячут операции от пошагового исполнения — конфликт DOCS-01), broadcasting, батчи
- Operator overloading в TS невозможен — «похожесть на Python» = имена методов: `x.matmul(W).add(b).tanh(); L.backward()`

Отвергнуто: чистый micrograd-порт A (MNIST ~5–15 с/эпоха, ~10⁸ объектов); полный PyTorch-слой C (~1200 LOC, Module прячет ops).

## R2 — Доменная модель и нейминг ✅ РЕШЕНО

**Решение (вариант D «словарь студента + прогон» + изолированная библиотека):**

```
src/tensor/            ← БИБЛИОТЕКА (ядро, выносимое отдельно: move + package.json)
  tensor.ts            класс Tensor: data, grad, requiresGrad, backward()
  ops.ts               matmul, add, tanh, sigmoid...
  functional.ts        F: функции потерь
  optim.ts             SGD: step(), zeroGrad()
  value.ts             скалярное ядро (математика micrograd)
  expanders.ts         ленивые раскрытия drill-down per-op
  model.ts             MLP: слои, веса, forward()
  trace.ts             StepRecord + recorder-типы
  index.ts             ЕДИНСТВЕННАЯ точка входа (публичный API)
src/run/               ← ПРИЛОЖЕНИЕ: политика прогона
  runState.ts          RunState: эпоха, шаг, фаза, drill, mode
  history.ts           график лосса, таблица весов по эпохам (после R3)
```

**Правила границы:** внутри `src/tensor/` — ноль импортов из приложения; приложение импортирует только через `index.ts`; проверка `no-restricted-imports` + тест границ в CI.

**Переименования:** `src/player/` → `src/run/`+`src/trace/`(+`src/tensor/`); `MockTrace`→`RunTrace`; `PlayerState`→`RunState`; `usePlayer`→`useRunSlice`; `StepPanel`→`OperationPanel`; `stepRows`→`operationRows`; тесты → `tests/run/`, `tests/trace/`; глоссарий EN↔RU. UI-строки и e2e-селекторы не трогаем (0 правок). Агентные имена (Player/Trainer/Learner) — табу.

## R3 — Эпохи и живой тренинг ✅ РЕШЕНО (в редакции пользователя)

**Решение (forward-only + сброс, как реальное обучение):**
- **«Назад» убрано полностью** — ни кнопки, ни клавиатуры (только →/Space). UX-01 удаляется из требований
- UI: `[Сброс] [Шаг →] [Запустить эпоху ⏩]`; экран завершения эпохи (L до/после, точность) → следующая эпоха, бесконечно
- Fast-forward: вся эпоха без пошагового UI + анимация потока (record: false)
- Индикатор: «Эпоха N · пример K · шаг M»
- **Reload = сброс** (URL несёт только сценарий; DOCS-05 AC «та же ссылка → то же состояние» меняется на «честный сброс» — DOCS-04 это уже допускал). Офлайн после загрузки (service worker) сохраняется
- **История:** график лосса (по шагам/эпохам) + таблица весов (строки = веса, столбцы = эпохи); опция «история по выделенному блоку/операции» — бэклог (обсудить к MNIST)
- **Python-pipeline удалён полностью**: `tools/reference/gen_mock_trace.py` и `src/data/xor-trace.json` удаляются; никакой сверки с micrograd. NFR-02 переформулируется: корректность операций = юнит-тесты с **захардкоженными эталонными константами** (forward + градиент на op; контрольные значения снять с xor-trace.json один раз перед удалением)
- Стартовые веса — фиксированные константы в конфиге сценария (воспроизводимость демо)
- Чекпойнты на эпохи — не нужны (назад нет, reload = сброс)
- Внутренняя самосогласованность остаётся юнит-тестом: `advance()×N === fastForward(N)` (без Python)

**Требует обновления при рефакторинге:** корневой REQUIREMENTS.md (DOCS-01 backward-edge AC, DOCS-05 reload AC, UX-01 удалить, NFR-02 переписать), `.planning/REQUIREMENTS.md` (UX-01), тесты/e2e на back-step переписать.

## R4 — Реактивность ✅ РЕШЕНО

**Решение (a) «один корень + селекторы» + декоратор как будущее расширение:**
- Модульный синглтон `export const run = new TrainingRun()` + селекторный хук `useRunSlice(sel)` поверх `useSyncExternalStore`; селективные перерисовки через `Object.is` на срезе; производные — в селекторе (`r => r.lossHistory.at(-1)`)
- Классы `src/tensor/` остаются фреймворк-независимыми (реактивен только корень прогона в `src/run/`)
- 0 зависимостей, 0 изменений сборки, Float64Array работает, DevTools-прозрачность (`window.__run = run`)
- **Расширение на будущее (санкционировано, не сейчас):** собственный `@reactive` декоратор (~70 LOC, per-field подписки, plain-значения, не-React-подписчики через `onField`); проверенный код и подводные камни (transform-плагин сборки, replace-дисциплина коллекций, keys/JSON) — `.planning/reviews/01/R4-reactivity.md` § Декораторы
- Триггеры пересмотра: live-режим R2+ с не-React-подписчиками; кадр >16 мс; TC39 Signals Stage 3
- Отвергнуто: Preact/TC39 сигналы (обёртки `.value`), MobX (Proxy, Float64Array мимо, +17 KB), Solid/Svelte (100% переписывание UI; руны = компилятор; stores = обёртки)

## R5 — Интерактивность ✅ РЕШЕНО

**Решение (связка Floating UI + CSS + точечный WAAPI):**
- **Тултипы**: `@floating-ui/react` (~10–15 KB gz, headless) — ховер на значение/звено → значение + вычисление (формула с подстановкой) + градиент/обратное значение; данные из `resolveRef` (mini-drilldown tier); a11y через useFocus/useDismiss (UX-04)
- **Подсветка активного звена**: CSS-transitions (обводка/тинт активной op)
- **Анимация потока forward/backward**: «бегущий пунктир» `stroke-dashoffset` с направлением по фазе шага (`data-flow="forward|backward"` на svg + один CSS-селектор) — видно, куда течёт сигнал/градиент; ~50 строк CSS, 0 зависимостей; масштабируется на fast-forward эпох (R3) и MNIST (агрегированный вентиляр входов)
- **WAAPI** — точечно для one-shot-эффектов (cancel-on-cleanup, гейт reduced-motion)
- **Анимации = презентационный слой поверх мгновенного обновления состояния** (A-8 UI-SPEC переформулируется); FLIP не нужен (слоты стабильны)
- **e2e-детерминизм**: `page.emulateMedia({ reducedMotion: 'reduce' })` в beforeEach всех скриншот-тестов
- **Лекционный режим**: `.lecture` анимации НЕ выключает (поток — дидактика); `@media print` останавливает пунктир
- Отвергнуто: Framer Motion (~30–45 KB, козырь layout/FLIP отсутствует), GSAP (лицензия), react-spring, d3-transition (dual ownership), SMIL (игнорирует reduced-motion), Canvas-частицы (отложено до MNIST-материала)

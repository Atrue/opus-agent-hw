## Functional Requirements

### DOCS-01. Пошаговое исполнение walkthrough с числами
**Из VP (студент)**: «Пошагово исполни forward- и backward-pass нейросети сам — и увидишь каждый градиент числом» (docs/02, сегмент 1).

Пользователь сам исполняет каждый шаг forward- и backward-pass готового сценария и видит входы, выходы, активации и градиенты операции числами; видна позиция в маршруте (шаг N из M).

**Acceptance criteria**
- Happy path: **Given** открыт сценарий «XOR на MLP» в начальном состоянии, **When** пользователь нажимает «Шаг» на первой операции forward-pass, **Then** отображаются входы, выход и результат операции конкретными числами, а индикатор маршрута показывает «шаг 1 из M».
- Edge case: **Given** пользователь находится на последнем шаге backward-pass, **When** нажимает «Шаг», **Then** walkthrough корректно завершается (итоговая сводка, предложение следующего сценария), а не падает и не показывает пустое/NaN-состояние.

### DOCS-02. Drill-down: диаграмма → слой → операция → число
**Из VP**: «drill-down: диаграмма архитектуры → слой → операция → отдельное число» (docs/02, How).

С любого уровня визуализации можно углубиться до отдельного числа и понять его происхождение (связь «формула ↔ число ↔ картинка»).

**Acceptance criteria**
- Happy path: **Given** на экране диаграмма архитектуры сети, **When** пользователь кликает на слой, **Then** раскрывается список операций слоя; **When** кликает на операцию, **Then** видит её входы/выходы; **When** кликает на любое число, **Then** видит формулу и источник, из которого оно получилось.
- Edge case: **Given** пользователь drill-down'ом доходит до градиента на первом слое (предыдущих слоёв нет), **Then** панель корректно показывает границу графа (входные данные / старт цепного правила), а не пустой экран и не бесконечную навигацию вверх.

### DOCS-03. Прогрессия готовых сценариев XOR → спираль → MNIST
**Из VP**: «готовые сценарии с нарастающей сложностью: XOR → спираль → MNIST» (docs/02, How).

Библиотека сценариев с методическим нарративом; прогрессия подсказывает порядок, но не гейтит доступ (Community: «без искусственных лимитов», docs/05 п.4).

**Acceptance criteria**
- Happy path: **Given** пользователь завершил сценарий XOR, **When** открывает список сценариев, **Then** XOR отмечен завершённым, а «спираль» подсвечена как следующий рекомендуемый сценарий.
- Edge case: **Given** новый пользователь открывает «спираль» или MNIST, не проходив XOR, **When** сценарий загружается, **Then** он полностью доступен — принудительная последовательность отсутствует.

### DOCS-04. Нулевой порог: браузер, без регистрации, ссылка = продукт
**Из VP**: «ноль установки, без регистрации, ссылка = продукт»; «в браузере, за один клик» (docs/02; docs/01 п.5).

Любой сценарий открывается по прямой ссылке без установки и регистрации; время от открытия до первого выполненного шага < 1 мин (цель из docs/01 п.6).

**Acceptance criteria**
- Happy path: **Given** пользователь без аккаунта открывает ссылку на сценарий, **When** страница загружается и он выполняет первый шаг, **Then** от открытия URL до первого выполненного шага проходит < 1 минуты, без регистрации, установки и ввода данных.
- Edge case: **Given** пользователь уже проходил сценарий и открывает ту же ссылку повторно (аккаунта нет), **When** страница загружается, **Then** ссылка остаётся валидной, а прогресс либо восстановлен локально на устройстве, либо честно сброшен — без требования регистрации для продолжения.

### DOCS-05. Лекционный режим: живое демо без подготовки (преподаватель)
**Из VP (преподаватель)**: «Готовое интерактивное демо backprop для лекции: пошаговый проход на экране аудитории без подготовки и установки. Один сценарий — каждый семестр» (docs/02, сегмент 2).

Сценарий воспроизводим пошагово на проекторе; состояние переживёт перезагрузку по той же ссылке (повторное использование каждый семестр).

**Acceptance criteria**
- Happy path: **Given** преподаватель открыл ссылку сценария на ноутбуке с проектором без какой-либо установки, **When** исполняет шаги синхронно с рассказом, **Then** каждый шаг отображается читаемо с дальних рядов и маршрут прохода остаётся детерминированным при повторении.
- Edge case: **Given** во время лекции обрывается сеть после загрузки страницы, **When** преподаватель продолжает нажимать «Шаг», **Then** шаги продолжают исполняться (все вычисления на клиенте), а перезагрузка страницы по той же ссылке возвращает то же состояние маршрута.

### DOCS-06. Встроенный замер прироста понимания (выведено из рискованного допущения)
> Выведено из STATE.md: самое рискованное допущение — H1/H2 («пошаговость даёт прирост понимания > 20%; преподаватели готовы встроить»). Без этого требования его нельзя проверить внутри продукта; сам по себе «тест в тренажёре» — трение, которое иначе никто бы не добавил. Инструмент валидации H1 на каждом пилоте.

**Acceptance criteria**
- Happy path: **Given** пользователь начинает сценарий, **When** ему предлагается пропускаемый pre-тест (5 вопросов), **When** он завершает walkthrough и проходит post-тест из тех же 5 вопросов, **Then** система считает индивидуальный прирост баллов и пишет его в анонимную агрегированную аналитику (материал A/B для H1).
- Edge case: **Given** пользователь пропустил pre-тест, **When** продолжает проходить walkthrough, **Then** доступ ничем не ограничен (гейтинг запрещён — North Star важнее замера), post-тест всё равно предлагается, а его данные помечаются как «без базовой линии» и не портят агрегат.

## Non-Functional Requirements

- **NFR-01. Скорость шага**: один шаг любого сценария, включая MNIST, — < 100 мс на среднем ноутбуке без GPU (guardrail из docs/01 п.6).
- **NFR-02. Корректность чисел**: 100% операций каждого сценария покрыты автотестами против эталонной реализации (reverse-mode autodiff, референс — micrograd/PyTorch на тех же весах); относительное отклонение ≤ 1e-6 (guardrail «доверие к числам» — продукт теряет смысл при опечатке в градиенте).
- **NFR-03. Архитектура нулевой себестоимости**: статик-хостинг; все вычисления в браузере клиента (JS/WASM), серверных вычислений нет; переменные издержки на пользователя ≈ 0; 100% сессий — без регистрации; аналитика — анонимная, готовый инструмент (Buy) (docs/01 п.5, п.6; docs/04 п.8).

## Out of Scope

Trade-offs из docs/01 (п.5) — осознанные решения (см. DECISIONS.md D-02…D-05):

| Мы выбираем | Вместо | Статус |
|---|---|---|
| Готовые сценарии в v1 | Свободный конструктор сетей + загрузка CSV | → R2 (D-02) |
| Пошаговость и наглядность | Производительность и масштаб моделей | MNIST — потолок v1 (D-03) |
| Браузер, ноль установки | Десктоп / облако / GPU | никогда в v1 (D-03, D-05) |
| Глубина: механика forward/backward | Широта: все архитектуры, RL, трансформеры | не наш сегмент (D-04) |
| Бесплатное ядро без регистрации | Монетизация на старте | гейт после R2-метрик (D-08, D-13) |

Также out of scope (docs/01 п.2; docs/05 п.2): исследователи/аспиранты, продакшн ML-инженеры, kaggle-участники, «курс по ML целиком»; реклама, продажа данных, B2C-подписка — закрытые двери (D-16).

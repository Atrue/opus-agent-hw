# JS/TS правила

## Синтаксис и стиль

- ES-модули: `import`/`export`, никаких `require()`
- Стрелочные функции для компонентов и хелперов; `function` — только если нужен hoisting
- `const` по умолчанию, `let` только при реальной необходимости, `var` — никогда
- Шаблонные строки вместо конкатенации: `` `port ${port}` ``
- Деструктуризация для props и параметров: `function Card({ title, onClick })`
- `===` / `!==` без исключений

## React (jsx/tsx)

- Функциональные компоненты + хуки. Классовые компоненты не создаются
- Один компонент = один файл, имя файла = имя компонента (PascalCase)
- Хуки — только на верхнем уровне компонента, в начале функции
- Используй существующие хуки (`useState`, `useMemo`, `useCallback`) прежде чем тащить библиотеку
- Данные из API — через `useEffect` с cleanup или кастомный хук, не inline в render
- Ключи в списках — стабильные id, не индексы массива

## Типы (ts/tsx, если добавится)

- Включай строгий режим (`strict: true`) в tsconfig при добавлении TypeScript
- Явные типы для экспортируемых функций, вывод — для локальных
- `unknown` вместо `any` на входах из внешнего мира (API, JSON.parse)

## Проверка перед коммитом

- После изменений в JS/TS всегда запускай `npm run build` — это единственная проверка типов/синтаксиса в проекте

# AGENTS.md — правила работы агента в репозитории opus-hw

Проект: **Backprop Trainer** — браузерный тренажёр, где студент сам пошагово исполняет forward/backward-pass нейросети и видит каждый градиент числом. Полный обзор — в [`README.md`](README.md).

## Обязательное чтение перед стартом работы (по порядку)

1. [`.planning/STATE.md`](.planning/STATE.md) — текущая фаза, план, статус, накопленный контекст (решения по фазам).
2. [`.planning/ROADMAP.md`](.planning/ROADMAP.md) — цель фазы, критерии, зависимости.
3. [`.planning/PROJECT.md`](.planning/PROJECT.md) — core value, ограничения, key decisions, **глоссарий EN↔RU** (правила именования обязательны).
4. [`REQUIREMENTS.md`](REQUIREMENTS.md) — канонические требования с acceptance criteria (DOCS-01…06, UX-\*, NFR-01…03).
5. [`DESIGN.md`](DESIGN.md) — дизайн-система.
6. Папка текущей фазы: `.planning/phases/<current-phase>/` — PLAN/SUMMARY/UI-SPEC/VERIFICATION/UAT.
7. [`DECISIONS.md`](DECISIONS.md) — журнал решений D-01…D-23 с обоснованиями; не принимать решений, противоречащих журналу.

Для GSD-воркфлоу контекст грузится автоматически в `.claude/CLAUDE.md` (PROJECT/STACK/CONVENTIONS).

## Воркфлоу

Работа ведётся через GSD-команды (см. `.claude/CLAUDE.md` § GSD Workflow Enforcement):

- `/gsd-fast` — тривиальная правка инлайн
- `/gsd-quick` — мелкие фиксы и правки доков
- `/gsd-debug` — исследование и багфиксы
- `/gsd-execute-phase` — исполнение планов фазы

Не делать прямых правок вне GSD-воркфлоу, если пользователь явно не попросил обход.

## Артефакты

Скрины «как было / как стало», референсы и прочие файлы — в [`artifacts/`](artifacts/README.md), имя `YYYYMMDD-<slug>.<anyformat>` (коммитится, ведётся инвентарь в `artifacts/README.md`). Рабочие captures ревью/UAT — в `.planning/ui-reviews/` (не коммитятся).

## Жёсткие ограничения

- **NFR-01:** шаг < 100 мс (включая MNIST в будущем) — без WASM, чистый TS/float64.
- **NFR-02:** ≤ 1e-6 против эталонных констант (`tests/tensor/etalon-constants.ts`); инварианты «drill-down = движок» и «пошагово = fast-forward» обязаны быть зелёными; snapshot-матчеры для чисел запрещены.
- **NFR-03:** никаких серверов; вычисления только на клиенте; аналитика анонимная, подключается позже через тонкий facade.
- **Прогон forward-only:** «шаг назад» не добавлять; reload = честный сброс; URL несёт только `#scenario=`.
- **Границы модулей:** публичный вход тензорной библиотеки — только `src/tensor/index.ts` (enforced oxlint); UI-слой не лезет вглубь движка.
- **Тесты/линт обязаны быть зелёными** перед завершением любой задачи: `pnpm test && pnpm lint` (e2e — `pnpm e2e`).

## Постоянные правила (от пользователя, не обходить)

1. **Store-библиотеки не вводить** без явного вопроса пользователю с обоснованием «зачем».
2. **Новые npm-пакеты не ставить** без sanctioned-чекпойнта: сверка легитимности (владелец, версия, вес) + подтверждение пользователя`.
3. **Именование по глоссарию** (PROJECT.md)
4. **Пользовательские строки — RU-first**, изолируются в строки-модули.
5. **dangerouslySetInnerHTML запрещён**; формулы drill-down — только из чисел сценария.

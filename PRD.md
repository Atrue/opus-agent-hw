# PRD — BugTrace (система багрепортов)

Версия: 1.0 · Дата: 2026-11-24 · Схема: `architecture.md`

## 1. Проблема и цель

Багрепорты о повторяющихся проблемах приходят многократно и с неполными описаниями, дубли не
видны отправителю. Цель — централизованный приём багрепортов, где AI достраивает описание по
скриншоту, проставляет теги и находит похожие баги, чтобы модераторы быстрее видели повторы.

## 2. Роли

| Действие | user | moderator | admin |
|---|:---:|:---:|:---:|
| Регистрация / вход (email + пароль) | ✓ | ✓ | ✓ |
| Отправить баг (title, description, скрин опц.) | ✓ | ✓ | ✓ |
| Видеть свои баги (любые) | ✓ | ✓ | ✓ |
| Видеть все решённые баги | ✓ | ✓ | ✓ |
| Видеть все баги (включая чужие нерешённые) | — | ✓ | ✓ |
| Редактировать баг (title/description/tags/скрин) | — | ✓ | ✓ |
| Пометить решённым | — | ✓ | ✓ |
| Видеть список похожих багов | — | ✓ | ✓ |
| Удалять баги | — | — | ✓ |
| Управлять ролями | — | — | ✓ (Dashboard/admin API, вне UI v1) |

Роль хранится в JWT (`app_metadata`); аноним — только экраны входа/регистрации.

## 3. Пользовательские сценарии

- **US-1 Вход.** Регистрация открыта, роль по умолчанию `user`.
- **US-2 Отправка бага.** Title + description, скриншот — один, опциональный
  (PNG/JPEG/WebP ≤ 5 МБ). После создания автоматически запускается AI-пайплайн; баг виден
  в «Моих багах».
- **US-3 Ленты пользователя.** «Мои баги» (любые статусы) и «Решённые» (все пользователи).
  Чужой нерешённый баг недоступен (404, факт существования не раскрывается).
- **US-4 Решённый баг.** Пользователь видит title, description, скрин, теги, автора, даты.
- **US-5 Очередь модератора.** Все баги, фильтры (статус, тег, поиск), пагинация.
- **US-6 Закрытие.** Moderator/admin помечает `resolved`. Баг появляется в «Решённых» у всех.
- **US-7 Правки.** Только staff правит title/description/теги и помечает решённым; автор свой
  баг после отправки не редактирует.
- **US-8 AI-помощь.** Автоматически после создания бага (и после загрузки скриншота):
  1) описание по скрину, если описание пустое; 2) теги по тексту (≤ 5 строк);
  3) до 5 похожих багов (решённых и нет) — списком id.
  Список похожих видят только staff; связи отображаются двусторонне, в БД — одна запись.
- **US-9 Удаление.** Admin удаляет баг (скриншот удаляется вместе с багом).

## 4. Функциональные требования

- **FR-1 Auth:** Supabase Auth, email + пароль; роль в JWT `app_metadata`
  (`user` / `moderator` / `admin`).
- **FR-2 Создание бага:** `title` обязателен, `description` опционален, скриншот 0–1 шт.
- **FR-3 Видимость:** свои — всегда; чужие — только решённые; staff — все. Обеспечивает RLS,
  невидимые объекты — 404.
- **FR-4 Статусы:** `open` → `resolved`, меняет только staff.
- **FR-5 Теги:** список строк на баге; ставит AI, правит staff; нормализация (lowercase,
  без дублей) — на API.
- **FR-6 Похожие:** до 5 ссылок (id других багов) на баге; видны только staff.
  Связи хранятся в отдельной таблице `bug_links` (FK с каскадным удалением, уникальность
  пары), при чтении отображаются двусторонне.
- **FR-7 AI:** запускается автоматически после создания бага и после загрузки скриншота
  (асинхронно, `after()`); ключи только на сервере; результаты пишутся в колонки бага через
  RPC, история операций в БД не ведётся; отдельного ручного роута AI нет.
- **FR-8 Лимиты AI:** в коде API (на баг и на частоту запросов), отказ → `429`.
- **FR-9 Скриншот:** приватный bucket, отдача через signed URL с проверкой видимости.
- **FR-10 Ленты:** фильтры по статусу/тегу, поиск по тексту, пагинация.

## 5. Нефункциональные требования

- Единственный барьер доступа — RLS в PostgreSQL; service role — только на сервере.
- CORS: белый список origins; куки httpOnly, SameSite=Lax.
- Сбой AI не мешает созданию бага и не ломает страницу; AI-шаги независимы.

## 6. Вне рамок v1

Комментарии, несколько скриншотов, правка бага автором, статусы `in_progress`/`duplicate`,
резолюция-текст, reopen, история AI-вызовов, уведомления, роли через UI, интеграции с Jira.
